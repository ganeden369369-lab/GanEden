# Phase 2 — Mentor Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user can open chats with Eden (the AI mentor), get streamed replies grounded in her numbers, goals and a cross-chat memory, within the free-tier cap — running locally end-to-end against a mock AI provider, with the real Anthropic provider implemented behind the same interface.

**Architecture:** `packages/prompts` (pure TS: persona, system-prompt builder, memory-extraction prompt + schema) is imported by both Vitest and the Deno edge functions. `supabase/functions/chat-send` authenticates the user JWT, enforces the cap and global budget, assembles context, streams SSE to the app, persists the assistant message, then extracts memory facts and titles the chat in the background (`EdgeRuntime.waitUntil`). The app reads chats/messages via `supabase-js` + TanStack Query and streams replies via `fetch` (web) / `expo/fetch` (native) into a Zustand streaming store. Phase 2 opens with the hardening the Phase 1 final review required.

**Tech Stack:** as Phase 1, plus Deno edge functions (`@anthropic-ai/sdk` via `npm:` specifier), `expo/fetch`, Deno test.

**Spec:** `docs/PRD.md` (F2 Mentor chat, §7 memory), `docs/ARCHITECTURE.md` (§5 `chat-send`, §6 AI layer).

## Global Constraints

- All Phase 1 constraints hold (TS strict, `src/ui` only, logical spacing, no raw hex in screens, i18n keys added to BOTH `en.json` and `he.json`, commit per task).
- **AI provider is config:** `AI_PROVIDER=mock|anthropic` (function env). Local dev and all automated tests use `mock`. The `anthropic` provider uses `@anthropic-ai/sdk` exactly as documented: `client.messages.stream({ model, max_tokens, system: [{type:'text', text, cache_control:{type:'ephemeral'}}], messages, thinking:{type:'adaptive'}, output_config:{effort:'low'} })`, iterate `content_block_delta` / `text_delta`, `await stream.finalMessage()` for usage and `stop_reason`; `stop_reason === 'refusal'` → the Mentor-voice fallback text. Model ids come from env `CHAT_MODEL` (default `claude-sonnet-5`) and `GEN_MODEL` (default `claude-sonnet-5`). No key is available on this machine; the anthropic path is reviewed, not executed.
- **Cap:** `check_and_increment_usage` (rpc, service role) before generating; `-1` → SSE `cap` event, HTTP 200 (SSE) — never generate. Global `spend_daily.usd > DAILY_BUDGET_USD` (env, default 20) → SSE `error` with code `budget`.
- **SSE contract** (`text/event-stream`, one JSON object per `data:` line, `event:` names): `meta {chatId, userMessageId, assistantMessageId, remaining}` → `delta {text}`* → `done {status:'complete'|'partial', title?}` | `cap {remaining:0}` | `error {code:'budget'|'provider'|'auth'|'bad_request', message}`.
- **Persona is a draft.** Eden has not supplied voice samples; `packages/prompts/src/persona.ts` is written from PRD §3 tone rules and is marked `PERSONA_VERSION = 'draft-0.1'`. No fabricated biographical claims about Eden. Safety rules from PRD §9 are in the system prompt.
- **Memory is cross-chat and user-controlled:** facts inserted by the service role with `source_chat_id`; the user can delete facts (RLS delete policy exists). Deleting a chat never touches memory (D9).
- **Rulings (controller, 2026-08-28):** (R1) memory extraction runs in-process after each assistant turn via `EdgeRuntime.waitUntil`, not pgmq — cost if wrong: extraction latency shares the function's CPU budget; revisit with a queue when volume warrants. (R2) NativeWind + Tailwind are removed (unused since the design system is inline-styled); D12 in ARCHITECTURE becomes "inline styles + tokens". (R3) `today_quote`/quotes are Phase 3; Home keeps its placeholder but gains the "Ask Eden" row. (R4) Chat list is the Chat tab's index; a conversation is `chat/[id]`; "new chat" = navigating to `chat/new` which posts the first message without a `chatId` and replaces the route with the created id.

export interface PromptContext {
  language: 'he' | 'en';
  firstName: string;
  numbers: NumerologyProfile;              // from @gan-eden/shared
  meanings: Record<string, { title: string; body: string }>; // key `${type}:${value}`

export function buildSystemPrompt(ctx: PromptContext): { stablePrefix: string; userBlock: string };

export const MemoryExtractionSchema = z.object({

### Task 5: `chat-send` + memory + migration

**Files:** `supabase/functions/chat-send/index.ts`, `_shared/context.ts`, `_shared/memory.ts`, `supabase/migrations/0002_chat.sql`.

Flow (`POST`, JSON `{ chatId?: string; text: string }`; CORS headers on all responses incl. `OPTIONS`):
1. `userClient(req).auth.getUser()` → 401 `error auth` if none. Validate `text` (1–2000 chars) → 400.
2. `admin.rpc('check_and_increment_usage', { p_user })` → `-1` → SSE `cap`. Then read `spend_daily` for today → over budget → SSE `error budget`.
3. If no `chatId`: insert `chats` row (title null). Else verify the chat belongs to the user (404 otherwise).
4. Insert the user `messages` row. Load context (`loadChatContext`): profile (+ `parseNumbers`), meanings for the language, `personalCycles(dob, today)`, `memory_summaries.summary`, last 30 messages of the chat (before this one).
5. Open SSE; send `meta`. `provider.streamChat(...)` with `onDelta` → `delta`. On finish: insert assistant message (`status` complete, or `partial` if the client aborted / provider error after some text), `model`, tokens, `prompt_version = PERSONA_VERSION`; update `chats.last_message_at`; upsert `spend_daily` (+usd). Send `done`.
6. `EdgeRuntime.waitUntil(afterTurn())`: if the chat has no title → `complete(buildTitlePrompt)` → update title; `extractAndStoreMemory` → `complete(buildMemoryExtractionInput)` → `MemoryExtractionSchema.safeParse(JSON)`; on success insert new facts (skip texts already present, case-insensitive), upsert `memory_summaries` (`facts_hash` = sha-256 of sorted fact texts). Failures are logged, never surfaced.
`0002_chat.sql`: policy `own chats update` (title/archived) for authenticated; `create or replace function public.add_spend(p_usd numeric)` security definer (service only) doing the upsert; index `memory_facts(user_id, created_at)`. Apply live with `db query` (no reset).
Verification: `npx -y supabase@latest functions serve --env-file supabase/functions/.env.local` in the background (copy the example to `.env.local`, git-ignored); get a JWT with the Phase 1 OTP script pattern (sign in `phase2@example.com` via Mailpit); `curl -N -H "Authorization: Bearer <jwt>" -H "apikey: <anon>" -d '{"text":"היי עדן"}' http://127.0.0.1:54321/functions/v1/chat-send` shows `meta`, `delta`s, `done`; second call with the returned `chatId` continues; after ~2 s `select * from memory_facts` and `chats.title` are populated; the 6th call in a day returns `cap`. Paste outputs in the report. Commit `feat(functions): chat-send with streaming, cap, memory extraction and titles`.
